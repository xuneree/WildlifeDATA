# 模块 01 低保真交互原型 · V0.1

本轮评审“数据回收列表 + Excel 四步导入”。使用示例数据，不连接正式 API，不写业务数据库；视觉为灰度线框，尚未定稿。

## 打开方式

- [可点击 HTML](index.html)：下载后用桌面浏览器打开；所有样式、脚本和模板下载数据均包含在此单文件中，无需安装或启动服务。
- [九页 PDF](module01-low-fidelity.pdf)：用于快速审阅、批注或分享。
- [六个主页面总览](overview.png)：用于比较页面组织。
- [周期模板示例](工作与回收周期_模板示例.xlsx)：字段示例，不代表正式导入服务已上线。

HTML 的“选择本地文件”只演示文件选择，不解析真实 Excel；请用“载入含错误示例 / 已修正示例”体验完整校验流程。演示列表及纠错保存在页面内存中，刷新或“重置演示”会恢复初始数据，不具备持久化业务草稿功能。

## 推荐体验路线

1. 在数据回收列表尝试查询、分页、详情；已有记录可演示更正备注。手工补录提供少量补录示意，固定在示例区域，不代表完整位点选择器已完成。
2. 点击“Excel 导入”，下载模板，载入含错误示例并开始预校验。
3. 查看源行号、错误/冲突说明；筛选问题行、下载错误说明、查看冲突的已有记录。
4. 点击“演示：重传已修正文件”，核对待新增、跳过数量和跨二级区域/批次范围。
5. 勾选确认后提交，查看实际新增与重复跳过结果，再查看列表。
6. 再次导入相同已修正示例，体验全部重复、不重复新增。
7. 使用顶栏“演示场景”分别体验全部重复、并发冲突、通信中断。要从一套全新的数据开始，先点击“重置演示”。

## 本轮建议评审

- 列表筛选和列顺序是否符合查找习惯？
- 错误行、冲突和重复的区别是否清楚，下载说明后能否找到需要修正的原表行？
- 提交前的区域、批次和数量信息是否足以核对？
- 返回列表、继续导入和已有记录纠错的位置是否顺手？

位点页面、完整账号/权限界面、正式 Excel 解析与服务端事务将在后续设计/开发完成；原型不冒充这些功能的实现。

## 验证与再导出

浏览器验证覆盖 10 组交互检查，结果见 [verification.json](verification.json)：筛选/分页、详情、下载、错误阻止、修正重传、真实重复跳过、冲突重校验、结果待确认、单条纠错和离开提醒。没有 JavaScript 运行错误，也没有外部网络请求。

`verify.py` 用于原型交互检查及重新导出截图/PDF，需要当前设计环境已有的 Python Playwright、Chromium、Pillow、pypdf 和 Noto CJK 字体；可通过 `PROTOTYPE_CHROMIUM` 指定浏览器。它不属于正式业务 CI，也没有向前后端项目新增依赖。此云环境的 Chromium 限制 file URL，验证时直接渲染同一 HTML 内容，不绕过浏览器策略或向外发布页面。
