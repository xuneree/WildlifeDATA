## 设计、原型与正式实现

总体需求和数据库设计是目标方案；野外表单 demo 是独立交互原型。它们的更新不表示正式应用、运行数据库或线上部署已经更新。

GitHub 基准 `572af212` 的正式应用仍为初始模型：schema.json 含 20 张业务表，仓库迁移最高为 0001。权限按旧 role/regions 实现，位点按 `(region, site_code)` 唯一，周期内保存 device_code。最新设计的工作组授权、机位实体和维护模型尚未落地。实际运行库必须现场查询 Alembic 版本，不能用仓库表数推断。

## 实现约束

- 新模型开发先盘点实际数据库、文件、权限和引用关系，再按数据库设计的迁移章节编写版本化迁移；不修改已执行的初始迁移。
- 工作组映射和成员迁移不能把旧区域/项目访问权直接扩大为整组；未知映射须明确核对。
- 媒体首次时间记录、XMP/Excel 匹配、独立拍摄和有效工作量需真实样例验证；布设跨度不自动等于有效工作日。
- 位点在位状态与相机工作状态、有效工作量分开处理；当前待同步的确认规则以交接页为入口。
- 被引用事实与审计历史保留，未知资料不填虚构值，实际验证记录见 [validation.md](validation.md)。

## 开发顺序

1. 完成当前已确认的位点动态状态请求，统一 guide 待同步事项、设计与正确表单 demo；核实原型版本和部署来源。
2. 盘点运行库与权限映射，按当前需求实施工作组、位点、机位和维护/周期模型。
3. 原始媒体、时间校准、鉴权预览与 XMP/Excel 标签导入，保证幂等、覆盖历史和事务一致性。
4. 个体档案、查询与工作量；统计参数和证据齐备后实现可复现的独立拍摄与 RAI。
5. 使用 Dell/WSL2、NAS 真实资料完成一期验收及备份恢复；后续功能按总体需求分期。
