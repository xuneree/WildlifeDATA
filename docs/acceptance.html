交付范围：需求V1.2 §3.1，相机位点、工作周期、维护与数据回收。

先打开哪一个文件？

本文件可以直接双击查看，但它是验收说明，不是运行中的系统。从交付分支下载源码ZIP并解压，进入包含 compose.yaml 的项目根目录。源码包内包含前端、后端、数据库迁移、Docker Compose、测试和操作说明。

当前云环境已通过健康检查，但本会话没有可用的网页预览或桌面打开工具，尚未提供可直接在你电脑访问的云端试用链接。云环境的127.0.0.1不是你电脑的127.0.0.1。

在Mac或Dell WSL2上启动

前提：安装并运行Docker Desktop（Dell启用WSL2）；终端中可运行 docker compose version 和 python3 --version。Dell请在WSL终端执行下列命令。运行需要首次下载容器镜像和依赖。

  1. 在终端进入解压后的WildlifeDATA文件夹。
  2. 执行：
python3 scripts/create-local-env.py
docker compose up -d --build --wait

出现服务启动成功后，在这台运行Docker的电脑浏览器打开 http://127.0.0.1:8080。

用户名默认为 admin。首次密码在本机新建的隐藏文件 .env 的 ADMIN_PASSWORD= 后面。Mac可按Command+Shift+.显示隐藏文件；不要把该密码或.env发到聊天中。源码包不包含云端账号、令牌或真实数据库数据。

建议使用新建的空白测试环境和下方合成数据；先不用真实相机坐标、视频或NAS。已有部署请先保留数据库备份，勿覆盖原.env；生成脚本会保留已有.env，且不会重置已有管理员密码。

结束后可执行 docker compose stop；再次启动使用 docker compose up -d --wait。不要执行 docker compose down -v，它会删除数据库卷。

你实际需要做什么？

先完成01、02、04、06、07这五项核心操作。你只需检查字段是否符合巡检习惯、数据能否正确保存和修改；不用安装开发测试工具或重跑29项自动测试。没有超过10条记录时可以暂不验证翻页。

05对拍的另一侧为同一位点新增 TEST701B，批次202608、状态已回收；填写维护与数据回收时间。A、B两台相机在同一批次各有一条记录；没有单独的设备管理表单。
06周期纠错编辑 TEST701A，先把结束时间改为早于开始时间并保存；然后恢复正确时间，将状态改为已回收并填写回收时间后保存。错误时间被拦截；修正后可保存；重新打开仍是修正后的数据。
07筛选与分页分别按位点、批次202608、未回收、有异常查询；再点击重置。记录超过10条时选择每页10条并翻页。列表和总数随条件变化；重置恢复可访问记录；翻页不重复、不漏掉记录。
08周期汇总筛选仅保留 TEST701A；若起止为6月1日08:00至6月3日08:00，检查统计。周期数1、记录周期时长2天；异常数量和回收数量与详情一致。此时长不是扣除停机后的有效工作日。
09重新登录退出登录，重新登录，再查询 TEST701 和对应周期。数据仍然存在；刷新整页后需重新登录属于当前会话设计。
10权限复核（协助项）管理员默认可验收前9项。只读、跨区域及坐标隐藏由开发者协助建立专用测试账号后验证。只读账号无新增/编辑入口，只能访问授权区域；无坐标权限时不显示精确坐标。这些已有自动测试覆盖。
