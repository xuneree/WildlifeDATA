# 模块1-相机管理 Demo

依据仓库基准 `1f9838a` 的 [页面设计指南](../../design/module01_design_guide.md)、[相机管理 V2.0](../../requirements/module01-camera-management-v2_0.md) 和 [Ant Design 使用基准](../../design/ant-design.md)，在原四表单上实现相机位点管理闭环。未修改用户维护的 guide。

## 使用

直接用现代浏览器打开源码包中的 `demo.html`，无需安装依赖。也可启动开发服务：

```bash
npm ci
npm run dev
```

构建与打包：

```bash
npm test
npm run package
```

输出为 `release/module01-demo.html`（单文件演示）和 `module01-demo.zip`（相同源码、测试、构建结果与 `demo.html`）。依赖由锁文件固定，沿用现有 React 18 / Ant Design 5 表单原型；正式应用的 React 19 / antd 6 接入另行实施。

## 演示流程

1. 从左侧“相机位点”进入列表；支持搜索、区域与在位状态筛选、按日期查询、分页及多选。
2. 点击“新增位点”，填写位点信息；生境调查从位点表单进入，不单独占用主导航。
3. 保存位点后自动进入操作记录；提交后回到列表，新位点排在首条。位点信息在第一步提交时已保存，操作未完成也可从详情继续新增。
4. 点击编号进入详情；位点信息可修改，调查历史可新增、修改、删除，操作及布设周期可查看、修改、新增。位点编号保存后只读，避免已有原型按编号关联的历史失联。
5. 勾选位点并导出，可多选坐标、轨迹、照片；坐标支持 KML / KMZ，附件按位点目录保留原文件名和内容，一并打包 ZIP。无所选附件时反馈为空，避免生成空包。文件重名以序号子目录区分。

KML 是 XML 地理标记文件，KMZ 是压缩包，标准入口为 `doc.kml`；本 demo 的 KMZ 仅包含位点坐标。奥维、两步路通常支持这两类文件，但没有在两款应用中进行实机导入验收。浏览器支持 File System Access API 时弹出保存位置选择器，否则采用浏览器默认下载方式。

## 数据与边界

- 这是独立浏览器交互 demo，未接入正式前后端、业务数据库或真实权限。其余模块仅保留禁用的导航位置。
- 工作组固定为“山西”，账号为 `demo-user`。基础记录存 localStorage，附件原文件存 IndexedDB，刷新后保留。清除浏览器数据、切换来源/浏览器会切换或清除这份演示数据；源码 ZIP 不包含填写的业务数据。
- 位点在位状态从已保存操作历史推导；未录入事实不自动认定为现场核实结果。相机上次配置现在从实际保存的操作记录取得，不再使用静态示例设备。操作和周期表单随当前位点切换，避免带入另一位点的内容。
- 沿用既有多段故障、UTC+8 校准、条件字段与调查“未调查”规则。业务记录、文件、审计跨存储的强事务、跨标签并发、正式权限、稳定 ID 的全链路改造与 Excel 批量导入仍属于正式实现。
- 原有草稿和历史不会自动转换成已建档位点；新列表只展示正式点击保存的位点记录。

## 验证

- `npm test`：在位状态与 KML/KMZ 导出回归测试。
- 浏览器脚本：先 `npm run dev -- --port 8765`，另一个终端执行 `npm run test:browser`；首次可 `npx playwright install chromium`，或用 `CHROMIUM_PATH` 指定已有 Chromium。`DEMO_URL` 可改为打包后的单文件地址，截图和测试 ZIP 写入 `work/browser-check/`。
- 浏览器检查：必填错误、新增位点两步闭环、安装/检查历史及周期、刷新恢复附件、调查新增、修改与删除、故障保存、90 秒 UTC+8 校准、KMZ/轨迹 ZIP 原文核对、1440px 桌面和 390px 手机布局；无页面运行异常。
- 单文件产物需与构建一起重新打包；包内 `demo.html` 是构建派生物，不是第二份手工源码。

## 源码

`src/manager.jsx` 为位点列表、详情框架和导出对话框；`src/engine.js` 保留四表单业务与记录逻辑；`src/files.js` 保存附件；`src/export.js` 生成 KML/KMZ/ZIP；`src/site-state.js` 计算历史在位状态；`scripts/package-demo.mjs` 打包同源交付物。
