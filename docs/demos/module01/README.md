## 运行

建议 Node.js 22 或更新的受支持版本。组件实际版本由锁文件固定：React 18.3.1、Ant Design 5.29.3、Vite 6.4.6。

```bash
npm ci
npm run dev
```

构建静态文件：

```bash
npm run build
python -m http.server 8765 --directory dist
```

浏览器打开 `http://localhost:8765`。ZIP 仅含同一份源码和说明，不包含依赖目录、站点凭据或部署身份。

## 已验证与正式接入边界

此版本已通过构建及浏览器检查：别名、下拉／多选、批次提示和选填、上传删除及数量边界、调查历史增删改、三类相机操作与只读编辑、故障和校准计算、账号日志、旧草稿恢复，以及桌面／手机布局。本次入库校验源码与压缩包一致，不代表生产数据库、真实权限或后端事务已经实现。

与正式实现的差异：本原型保留已审阅的 React 18／antd 5 组合；正式接入应按项目设计基准评估 React 19／antd 6，并减少原型组件适配层和内部 DOM 依赖。相机上一条记录、区域、项目和当前账号需要真实接口；原型以位点／机位／日期关联周期，正式模型应使用稳定 ID。敏感坐标权限、真实文件存储、并发与审计事务仍由正式系统实现。

## 建议用户补入 guide 的已确认需求

当前数据库 guide 的对象定义已更新为安装／检查／撤回，部分表字段及核实描述仍待同步。以下是本次对话确认的新规则，建议由用户同步维护，本文不直接修改 guide：

> 相机操作类型为安装、检查、撤回；检查涵盖回收和更换的具体动作，操作批次选填，撤回填写原因。工作组由全局上下文带入。布设周期默认无故障，可选填故障时间段与时间校准，不要求手填确认人和判断依据，日志取登录账号。现场正常自动确认是当前原型的简化规则，正式统计口径需与“未完整核实不按首末跨度统计”的既有原则明确衔接。

> 位点布设类型及启用状态由相机操作记录按查询时刻的在位数量推导，不在位点表单手填；0 台无布设/停用，1 台单侧/启用，2 台对拍/启用，故障仍算在位。

> 位点信息增加非必填网格编号，按文本保存；表单顺序为小地名、网格编号、关联项目。
