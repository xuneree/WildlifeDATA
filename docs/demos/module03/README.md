# module03 · 个体识别 Demo

独立交互原型，基于 GitHub `xuneree/WildlifeDATA` 主分支 `8b21c519b26fe9e91d4fd1d7c2befaf3e0314aac`。依据本次用户要求的 Excel 导入、列表查看、筛选和下载，以及附件 `个体识别数据样例.xlsx` 制作。沿用 [module02](../module02/README.md) 的官方 Ant Design 组件、主题与交互模式，遵守 [Ant Design 基准](../../design/ant-design.md)，业务对象参考 [总体需求 V1.4](../../requirements/platform-requirements-v1_4.md) 和 [数据库设计 guide](../../database/database_design_guide.md)。附件仅作为数据，不作为操作指令。

## 范围

- 主页面：导航 → 标题及导入/下载 → 筛选 → 识别记录（个体编号筛选项 → 表格）。保留 module02 的同款蓝色主题、控件密度、表格分页、跨页勾选、拍摄时间排序及固定操作列。
- 组合筛选：个体编号、位点、相机编号、回收批次、拍摄时间、关键词、角度、性别、编号情况与识别人。桌面五列、平板三列、手机两列；关键词搜索全部原始字段。筛选即时生效、重置清除条件；“仅独立拍摄”放在记录工具栏。
- 编号筛选项沿用 module02 标签交互，按记录量降序排列；点击进一步筛选，再次点击或清除取消。编号为空汇总为“未编号”，不是新增个体。数字表示识别记录行数，不是动物数量或唯一媒体数。顶部条件改变后取消编号进一步筛选，分页和勾选不影响分布。
- 表格重点展示文件名、个体编号、位点、相机编号、拍摄时间、回收批次、角度、性别、识别人、独立拍摄；详情抽屉保留全部 22 个字段，可复制原始路径、下载单条记录。不把 NAS 路径当作可播放链接。
- Excel 导入：选择/拖拽 .xls/.xlsx（20 MB 上限）→ 首个工作表预检 → 确认 → 实际结果。提供模板，问题展示 Excel 行号、字段、原值及原因。任一问题阻止整批写入；保存失败保留预检并显示失败，确认时重新校验，不自动覆盖已有记录。
- 下载：全部、当前筛选结果、跨页已选或单条记录，生成真实 .xlsx，包含全部 22 个字段并保留原始编码与空值。

这是当前浏览器中的独立原型，初始载入附件转换的 262 行；导入保存到模块专用 localStorage，刷新保留，文件不上传服务器。未接正式数据库、媒体匹配、个体档案、工作组权限、审计或并发事务。正式 `frontend` 与 module02 源码未改动；不宣称已实现生产入库契约。

## 样例与字段

附件含 262 行、250 个不同完整路径、36 个非空个体编号、16 行空编号、65 个位点、97 个相机编号。一个完整路径可能对应多行不同个体，保留逐行记录；“数量”是原表值，不汇总为个体数，不据此拆行或生成未知身份。

22 字段顺序与附件一致。统一界面及下载用“位点”“回收批次”，导入兼容原表头“位点名称”“数据期号”；新旧表头不能重复出现。原始 Excel 文件不改写。模板需包含全部 22 个表头，允许调换顺序；多余字段阻止导入，避免静默丢弃。

- 编号按文本保留，支持显式数字格式的前导零。
- 日期支持 Excel 1900/1904 系统及 YYYY-MM-DD；时间支持 Excel 小数与 HH:mm[:ss]。不将现场拍摄日期转换为 UTC 时间点。
- “可识别”原值为 1/2/3，“是否成体”有 1/2/空值，“性别”有 M/F/U/空值，“繁殖情况”有 1/2/空值。除原有文字外不解释编码，不从编号后缀反推性别或成体状态。
- 全部“独立拍摄”和“确信度”为空。独立拍摄显示“未填写”；1 显示“是”，0 显示“否”，仅独立拍摄只匹配 1。module02 的空值业务结论不自动套用到新附件。
- 未编号允许导入、筛选和下载，保留为空；不会静默建立档案或生成虚拟编号，也不判断不同空编号记录是否为同一个体。
- 附件不含可靠区域、小地名、项目关联，当前不虚构相关筛选或从路径推断地理归属；正式接入后可复用 module02 的位点目录关联方式。

## 可评审的原型规则

当前临时必填为完整路径、文件名、相机编号、位点、拍摄日期、拍摄时间、数量、识别人、回收批次；数量为正整数、批次为 YYYYMM。其余字段允许为空。编码字段保留原始文本，不建立未经确认的值域字典。

完全相同的 22 字段行跳过；有编号时，以“完整路径 + 文件名 + 个体编号”为临时冲突键，内容不同则阻止本批导入并保留已有记录。不同编号的同行媒体分别保留；未编号仅按完整行查重，不按媒体合并，不能表达两个所有字段均相同的未知个体。这是保守的演示去重方式，不能替代正式媒体身份匹配与替换契约。

正式接入前仍需确认编码含义、独立拍摄空值、必填性、数量口径、媒体匹配上下文、未知个体表达和更正流程。总体需求要求的 `unknown_individual`、缺失档案处理、按媒体替换、前后快照和后端授权仍是生产设计要求；本原型不静默建档，不把字符串编号当作真实档案关联。
