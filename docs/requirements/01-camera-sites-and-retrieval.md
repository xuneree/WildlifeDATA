全平台分期见[总体需求 V1.3](platform-requirements-v1_3.md)，本模块已确认规则保持不变。

### 本轮确认结果

| 决策 | 已确认内容 | 对需求的影响 |
|---|---|---|
| T01 | 同一位点、同一相机，每个回收批次只回收一次 | 保留周期三字段唯一性，不增加批次内回收序号 |
| T02 / T02a | 固定使用“一级区域—二级区域—位点”，例如“山西—和顺—位点 701”；每个位点都属于二级区域 | 不将二级区域称为保护区，不支持缺少二级区域的位点 |

| T05 | 本模块现场时间精确到日期 | 首次布设、工作起止及回收使用日期，不要求时分秒；不设置独立维护日期 |
| T06 | 支持 Excel 批量导入位点和回收记录 | 模板、预校验和结果反馈纳入本轮范围 |

| T08 | 位点编号在一级区域内不重号 | 同一一级区域下不同二级区域也不能重复编号；不同一级区域可使用相同编号 |

本次审阅已采纳停用/启用、位点改动、权限和 Excel 导入流程规则，并修订字段限制、默认值、固定选项和删除权限。具体固定选项词表待页面/数据字典设计时补齐，不在本稿中编造选项值。

## 1. 目标与范围

完成“建立相机位点 → 记录一次已结束的相机工作周期及维护/回收 → 查询历史 → 纠错”的操作闭环，并为下一个媒体模块提供可靠的周期归属。

| 本轮详细设计范围 | 与后续模块的边界 |
|---|---|
| 位点新增、详情、列表、筛选、编辑 | 地图底图、物种分布和生态分析另行设计 |
| 单侧/对拍位点及相机编号 | 不建立独立相机设备资产模块（基准） |
| 已结束周期的维护、回收和异常记录 | 本轮不增加进行中周期、巡检排程或提醒服务 |
| 周期新增、详情、列表、筛选、纠错 | 影像上传和播放由媒体模块实现 |
| 本模块区域访问、坐标访问、操作审计 | 账号管理界面与全平台权限策略在共享权限设计中统一 |

已确认：位点和工作/回收周期的 Excel 批量导入均纳入本模块交付；预校验、重复识别、权限检查和逐行结果反馈必须同时设计。位点停用和重新启用也纳入本轮范围。

## 2. 业务对象与含义

### 2.1 位点

一个位点代表一处监测位置，包括编号、所属区域、地理位置和生境。单侧/对拍是位点的布设方式，不是工作周期的回收状态（基准）。

已确认：采用固定的“一级区域 → 二级区域 → 位点”结构。例如一级区域为“山西”、二级区域为“和顺”、位点编号为“701”。二级区域不是保护区，界面、需求、后续 API 说明统一使用准确名称，不将完整层级路径拼成一个自由文本字段。

每个位点必须归属一个二级区域，每个二级区域归属一个一级区域。不存在跳过二级区域、直接归属一级区域的位点。二级区域名称应结合所属一级区域区分，不要求在全平台名称唯一。

每个位点关联明确的二级区域，以不可变的内部 ID 关联周期。已确认 T08：按“一级区域 + 位点编号”保证唯一性，包括该一级区域下所有二级区域。比如“山西—和顺—701”存在后，山西下其他二级区域不能另建 701；另一一级区域可以有自己的 701。区域改名不改变内部 ID，编号纠错不生成新的位点内部 ID。

停用位点仍占用原编号，避免旧影像和新位置混淆；重新启用继续使用原内部 ID 和原编号。跨一级区域调整归属时，也要重新检查目标一级区域的编号冲突。

对拍相机编号可使用 `701A`、`701B`，但不强制所有现场编号符合此格式。相机型号在各周期记录，以保留换型历史（基准）。

### 2.2 工作与回收周期

一条记录对应“一处位点的一台相机，在一个已经结束的工作周期中的运行情况，以及期末维护/数据回收”（基准）。

例：位点 `701` 为对拍位点，2026 年 8 月取回上一周期数据，则 `701A`、`701B` 分别记录，各自对应批次 `202608`；A 已回收、B 未回收可以同时存在。

回收批次表示取回或开展期末维护的批次，不表示影像全部在该月拍摄。工作结束日期与数据取回日期分别保存，不相互自动覆盖。删除独立的期末维护日期字段，保留维护人员与备注；页面、Excel 模板和数据库设计均不再要求填写维护日期。

已确认 T01：同一位点、同一相机，每批次只回收一次。周期按“位点 + 相机编号 + 回收批次”唯一；重复录入时引导查看或更正现有记录，不覆盖，不增加批次内回收序号。不同相机及不同批次可以各自有记录。

## 3. 使用者与权限

登录后按区域限制数据访问。管理员可查看全部精确坐标，区域工作人员可查看授权范围内精确坐标；只读账号的精确坐标权限单独授权。

已确认 T03：各区域工作人员维护本区域，管理员管理全部。下表已按本次审阅确定工作人员的区域写入与坐标权限。现有代码仅具备管理员写入与普通账号只读，需要后续开发区域写入能力。

| 使用者 | 位点和周期查询 | 新增/修改 | 精确坐标 |
|---|---|---|---|
| 管理员 | 全部区域 | 全部区域 | 全部区域 |
| 区域工作人员 | 被授权范围 | 被授权范围 | 被授权范围 |
| 只读账号 | 被授权区域 | 不允许 | 独立授权 |

已采纳的权限规则：

- 后端对列表、详情、写入和后续导出都验证区域权限；不能仅在页面隐藏操作按钮。
- 支持按一级区域或二级区域授权；一级区域授权覆盖其下全部二级区域和位点，单个二级区域授权不包含同一级区域内其他二级区域。工作人员能在授权范围内录入、修改并查看精确坐标。
- 无坐标权限时不返回精确经纬度；页面显示“无位置访问权限”，不要将隐藏值误显示为未填写。
- 只读账号不能编辑位点；任何不涉及坐标的部分更新均不得以未提交字段或隐藏占位值清空原坐标。
- 变更位点所属区域仅允许管理员操作；关联周期及媒体访问范围将随位点区域改变，必须提示影响并记录审计。
- 用户本轮选择区域工作人员直接维护，未选择负责人审核；本稿不增加“提交—审核”流程。如后续提出审核需求，再单独补充。

## 4. 位点字段

原有字段必填性来自数据库设计；固定两级区域归属和日期精度是本轮已确认的需求变更。字段与数据库设计 V1.3 对齐；业务日期使用 DATE，并以 _date 命名。原字段映射见数据库设计修订说明。现有 region 文本字段不足以完成层级管理。

| 业务字段 | 数据字段 | 必填 | 规则与说明 |
|---|---|---|---|
| 位点编号 | site_code | 是 | 一级区域内唯一；最长 20 字符；保留文本，不将前导零转成数字；去除首尾空格 |
| 所属范围 | region_level1_id / region_level2_id | 是 | 先选一级区域，再选其下二级区域；位点必须归属二级区域，详情显示完整路径；后续迁移现有 region 文本 |
| 首次布设日期 | first_deployed_date | 否 | 日期格式 YYYY-MM-DD；允许历史资料未知，不填虚构时刻 |
| 布设方式 | deployment_type | 是 | 单侧 single / 对拍 paired；默认单侧 |
| 位点状态 | site_status | 是 | 启用 active / 停用 inactive；新建默认启用，状态变更记录审计 |
| 经度 | longitude | 否 | WGS84，范围 -180～180 |
| 纬度 | latitude | 否 | WGS84，范围 -90～90；经纬度一起填或一起为空 |
| 海拔（米） | elevation_m | 否 | 不把低于海平面的合法值直接判为错误；不自动从地图推算 |
| 地形 | terrain_type | 否 | 最长 20 字符；固定选项，词表待补齐，不允许任意自由文本 |
| 植被 | vegetation_type | 否 | 最长 20 字符；固定选项，词表待补齐，不允许任意自由文本 |
| 环境属性 | environment_type | 否 | 最长 20 字符；固定选项，词表待补齐，不允许任意自由文本 |
| 备注 | notes | 否 | 补充现场信息；不代替必要字段 |

已采纳的位点改动规则：

1. 编号或字段录错可以更正，内部 ID 和历史关联保持不变；修改保存前检查编号冲突。
2. 位置录错可以纠正并保留修改前后值。已确认 T07：真实迁移到新位置时建立新编号及新位点内部 ID；旧周期和媒体继续关联旧位点，不批量改写为新位置。
3. 单侧改为对拍不删除原周期；历史周期以原相机编号保留。后续页面须避免将位点当前布设方式误标为全部历史周期的布设方式。
4. 具有周期记录的位点不可直接删除；未被引用的误建位点可由具有该范围位点新建权限的账号删除并记录操作，不限定管理员；区域工作人员不能删除授权范围之外的位点。已确认支持停用和重新启用，不用删除表达停用。

已采纳的停用与重新启用规则：

- 停用不删除历史周期、媒体或其他关联数据；历史查询、筛选和统计仍按原归属保留。列表可按启用/停用状态筛选。
- 停用后，常规新增周期的位点选择默认只列启用位点；允许从停用位点历史详情补录既往周期和更正历史资料，并明确提示当前已停用。
- 原位置恢复监测时可重新启用，沿用原 ID 和编号；新位置必须另建位点，不以重新启用替代。
- 有该区域写入权限的工作人员可停用/重新启用本区域位点，管理员可操作全部；切换状态也须保存审计。
- 位点当前状态不反推历史每一天的监测状态，也不自动关闭或改写任何工作周期。若将来需要精确停用时段统计，再单独设计生命周期历史。

## 5. 工作周期、维护与回收字段

| 业务字段 | 数据字段 | 必填 | 规则与说明 |
|---|---|---|---|
| 所属位点 | site_id | 是 | 从有权访问的位点选择，不能只凭相机编号推断 |
| 相机编号 | device_code | 是 | 最长 20 字符；文本保存，如 701A |
| 相机型号 | device_type | 否 | 最长 20 字符；保留该周期型号 |
| 工作开始日期 | work_start_date | 否 | 日期格式 YYYY-MM-DD；不确定可以留空 |
| 工作结束日期 | work_end_date | 否 | 已填写起止日期时，结束不得早于开始；不默认等于回收日期 |
| 维护人员 | maintenance_by | 否 | 初期保存姓名文本；多人录入形式在交互设计时统一 |
| 数据取回日期 | data_retrieval_date | 否 | 实际取回日期，格式 YYYY-MM-DD；未回收仍可记录周期 |
| 回收批次 | data_retrieval_batch | 是 | 最长 20 字符；建议常规格式 YYYYMM；已确认同位点同相机每批次仅一条周期 |
| 数据回收状态 | data_retrieval_status | 是 | retrieved / not_retrieved；已取回但空卡或文件损坏仍为 retrieved，异常写备注 |
| 异常主类型 | issue_type | 否 | 建议选项见下文，不增加多个互相冲突的状态字段 |
| 备注 | notes | 否 | 其他异常、资料缺失说明和维护情况 |

异常类型建议：存储卡丢失、相机丢失、相机损坏、电池耗尽、其他；正常记录不填写异常类型。若同一周期有多个异常，首版建议选择主异常，其他写入备注；需要分别统计时再增加多异常结构。

校验与提示：

- 实际周期可以结束但起止日期未知；允许记录，显示“工作日期不完整”。
- 已确认 T05：首次布设、工作起止、回收均仅录入日期 YYYY-MM-DD，不要求时间或时区，不把未知时刻补成 00:00:00；保存、读取和导出须保持同一日历日期。数据库设计采用 DATE，API 使用日期字符串，不通过时间戳转换造成跨日。
- 此日期规则只针对本模块现场业务日期；系统操作和审计仍记录真实时间点，媒体拍摄时间继续在媒体模块单独定义。
- 同相机日期区间疑似重叠时提示核对，不自动合并或截断。只有日期时，同日结束/开始可能是正常换卡，不能仅凭边界同日判定重复工作。
- 未回收可填写原因和备注；不自动删除其工作周期，也不推断相机未工作。
- 已确认 T04：已取回但空卡、没有影像或文件损坏，仍记为“已回收”，在现有 notes 备注中说明；不新增数据质量字段、专门异常状态或强制结构化分类。“已回收”不等于“有可用影像”，也不等于“已导入影像”。媒体模块再提供实际入库文件数量。
- 工作周期时长不自动称为有效相机工作日。期内停机、开始/结束未知、重复区间等不适合据此计算精确工作量。

## 6. 操作流程与需要表达的信息

本节确定操作任务及信息需求；导航、布局、表单形态和视觉设计在需求确认后完成。

### 6.1 建立与维护位点

1. 查看有权访问的位点，可按一级区域、二级区域、编号关键词、布设方式和启用/停用状态筛选；采用分页，明确显示总量。
2. 新增位点，填写必填字段和已知现场信息；不要求为了保存而伪造坐标或首次布设日期。
3. 保存成功后进入位点详情，展示基础信息及工作/回收历史。
4. 更正资料，显示字段级错误或冲突；保存失败保留输入内容，数据库无部分修改。

### 6.2 登记一次回收周期

1. 已确认日常主流程为围绕同一回收批次一次录入多个位点。主入口组织为批次录入；从单个位点详情登记或更正仍作为辅助入口。
2. 逐台相机填写周期、型号、维护、回收状态和异常；对拍 A/B 独立保存，不强制两台均有数据。
3. 校验“该位点 + 该相机 + 该批次”是否已存在；若存在，阻止新建并引导查看已有记录，允许有权人员纠错。
4. 保存后可查询该周期详情；为下一模块提供明确周期 ID、位点、相机编号、批次和回收状态。

批量登记作为主工作场景，已确认主要采用“先在 Excel 整理，再批量导入”；交互方案见[批次录入交互草案](../design/module01-interaction-v0_1.md)。共同信息可由用户明确应用到选中记录，各相机的工作日期和回收状态仍可独立填写；不默认复制 A 相机的有效工作日期给 B 相机。网页表单用于少量补录和已有记录纠错；复杂网页批量表格编辑器不作为当前设计重点。具体页面组织仍须在交互稿中确认。

### 6.3 查询与纠错

- 位点列表：一级区域、二级区域、位点编号、布设方式、启用/停用状态；可进入详情。
- 周期列表：一级区域、二级区域、位点、相机编号、批次、工作起止、取回日期、回收状态、主异常；支持对应筛选和分页。
- 周期详情：完整字段、位点关联、关联媒体数量（媒体模块接入后）和修改历史。
- 建议按实际取回日期倒序；无日期时明确排序规则，不将未填写显示为当前日期。
- 建议未关联媒体的误建周期允许管理员删除；已关联媒体的周期不允许直接删除。
- 已关联媒体后，位点/相机/批次是媒体归属信息，建议普通编辑不能改变；需要更正归属时采用专门流程、说明原因、展示影响并记录审计。准确规则须在媒体模块共同确认。

### 6.4 Excel 批量导入（已采纳）

提供两份独立的 `.xlsx` 模板：“位点导入”和“工作与回收周期导入”。模板字段与手工录入保持一致，包含字段说明、必填标记和示例；不借导入新增另一套业务规则。

| 模板 | 主要内容与匹配规则 |
|---|---|
| 位点导入 | 一级区域、二级区域、位点编号、布设方式及已知可选字段；以“一级区域 + 位点编号”检查冲突，并核对二级归属 |
| 周期导入 | 一级区域、二级区域、位点编号、相机编号、回收批次、回收状态及可选日期/维护/异常信息；匹配已有位点，以“位点 + 相机编号 + 批次”检查冲突 |

已采纳的首版导入流程：

1. 下载模板并填表；位点编号、相机编号、批次列按文本保存，模板提示保留前导零。日期使用 Excel 日期单元格或明确的 YYYY-MM-DD 文本，不猜测存在歧义的日期写法，不接受含具体时刻的值。
2. 上传后先预校验，不立即写入。展示每行的一级/二级区域、匹配对象、计划新增/重复跳过/错误以及具体原因。
3. 使用已有区域字典，逐行检查层级关系、权限、必填、字段格式、日期、坐标及编号/周期唯一性。区域不存在或归属不符时反馈错误，不从拼写不确定的名称自动创建新区域。
4. 周期找不到对应位点时反馈错误；先完成位点导入再导入周期，不自动创建信息不完整的位点。停用位点的历史周期允许补录，并显示提醒。
5. 已存在且内容相同的记录标为重复并跳过；同一业务键但内容不同则标为冲突，不自动覆盖。首版 Excel 用于批量新增，不承担批量修改、改号、跨区域移动或状态切换；这些操作通过相应页面完成并保留审计。
6. 整批有错误时先反馈并修正，不部分写入；全部通过后由用户确认导入。正式提交时重新校验权限与并发冲突，同一事务写入本批新增记录及审计，失败全部回滚，重复记录保持不变。
7. 显示本次总行数、新增数、重复跳过数和失败/未导入情况；可下载逐行结果及错误说明。重复上传成功过的同一文件不会产生重复位点或周期。

补充建议：

- 文件内重复也必须识别；内容相同可去重并提示，不同内容使用同一键则报冲突。比较时仅按明确规则标准化空白、日期和空值，不猜测编码的大小写含义或删除前导零。
- 模板中的一级/二级区域列都必须在授权范围内；只有具备该范围位点新建权限的账号能导入位点与坐标；工作人员仅可导入授权范围内坐标，只读账号不能通过 Excel 写入。
- 导入结果或错误附件也受区域与坐标权限限制；表格导出时防止用户输入被当作公式执行。模板之外的宏或公式不作为业务值求值。
- 新位点建议默认启用。历史停用位点可先导入基础资料，再通过停用操作标记；是否在模板中支持初始状态可在模板设计时评审。

## 7. 审计与错误反馈

建议位点和周期的新增、修改、删除及跨区域调整记录账号、动作、对象 ID、时间和变更前后字段。精确坐标可能出现在审计中，审计访问须同样受坐标权限限制；普通无坐标账号不能借日志取回原坐标。

同次操作的业务保存与审计保存必须同成同败。编号冲突、越权、无效位点、日期不合法等错误以可理解的信息反馈；不要只显示通用“保存失败”。

不展示用户无权访问的位点详情；搜索、分页总数和筛选候选也不能泄露其他区域信息。

## 8. 与媒体模块的接口约定

基准：每条媒体属于一个明确的 camera_deployment，而非仅属于位点或回收月份。

建议媒体入库的周期选择项同时显示：区域、位点编号、相机编号、批次、取回日期和回收状态。跨周期同名文件不能仅凭文件名匹配。

未回收周期是否允许后来补录媒体，以及补录时是否更正回收状态，留给媒体需求共同确认；不因当前状态静默移动影像或创建另一条假周期。

## 9. 验收场景草案

本表作为后续开发的验收用例来源；不是当前已通过的测试清单。

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC01 | 新增单侧位点，仅填必填字段 | 保存成功，未知坐标和日期保持为空 |
| AC02 | 只填经度，或坐标超出范围 | 明确指出错误，无业务/审计残留 |
| AC03 | 同一一级区域下不同二级区域重复编号；不同一级区域同编号 | 前者阻止，后者允许；停用位点原编号继续保留 |
| AC04 | 对拍 A 已回收，B 未回收 | 同位点同批次生成两条独立记录，状态分别保留 |
| AC05 | 回收日期晚于实际工作结束日期 | 原值分别保存，不用回收日期覆盖工作结束日期 |
| AC06 | 结束日期早于开始日期 | 阻止保存并保留表单输入 |
| AC07 | 工作日期未知但已完成期末维护 | 允许记录，显示资料不完整，不推断有效工作日 |
| AC08 | 同位点同相机同批次重复登记 | 阻止重复新建，引导查看或纠正已有记录；不覆盖原记录 |
| AC09 | 区域账号查询或修改另一地区记录 | 列表、详情、筛选及写入均受权限约束 |
| AC10 | 管理员、工作人员和只读账号分别查看精确坐标 | 管理员全部可见，工作人员仅授权范围可见，只读账号按独立授权显示，不能编辑 |
| AC11 | 更正编号或周期资料 | 内部 ID 不变；关联不丢失，保留前后审计 |
| AC12 | 删除有周期的位点或有媒体的周期 | 阻止直接删除，说明已有引用 |
| AC13 | 多于一页的记录，筛选后翻页 | 总数及分页正确，不遗漏记录、不返回越权数据 |
| AC14 | 卡已取回，但为空或文件损坏 | 保存为已回收，异常写入备注，无额外数据质量字段 |
| AC15 | 仅授权“山西—和顺”的工作人员尝试修改其他二级区域记录 | 后端按授权范围阻止越权 |
| AC16 | 建立“山西—和顺—701”及尝试跳过二级区域建立位点 | 完整归属保存成功；缺少二级区域时阻止保存 |
| AC17 | 日期经录入、读取及导出 | 保持 YYYY-MM-DD，不要求时分秒，不因时区换日 |
| AC18 | 位点停用后查看历史，并补录历史回收记录 | 历史关联保留，允许明确的历史补录入口 |
| AC19 | 原位置重新启用；迁移到新位置 | 原位置沿用原 ID/编号；新位置使用新 ID/新编号，不移动历史证据 |
| AC20 | Excel 导入正确的位点，随后导入对应周期 | 预校验后明确确认，按模板规则新增并保留审计 |
| AC21 | 重复上传相同 Excel；同键不同内容 | 前者跳过不重复建档；后者报冲突，不覆盖旧数据 |
| AC22 | Excel 含未知区域、错误日期或越权行 | 逐行反馈原因；整批不写入，修正后重新提交 |
| AC23 | 导入预校验后，其他用户创建了相同业务键 | 提交时重新校验并回滚失败批次，不产生部分数据或无主审计 |
| AC24 | 位点编号、相机编号、相机型号或生境字段超出 20 字符 | 手工和 Excel 均拒绝，不静默截断；合法 20 字符可保存 |
| AC25 | 未选择布设方式；地形/植被/环境填写非词表值 | 布设方式默认单侧；非空生境字段只能使用对应固定选项 |
| AC26 | 区域工作人员删除本范围未被任何业务引用的误建位点 | 允许并审计；有任何引用或越权则阻止，不限管理员 |
| AC27 | 打开周期表单或导入模板 | 不包含期末维护日期；保留维护人员、工作起止和数据取回日期 |
