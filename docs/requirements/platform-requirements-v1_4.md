# 红外相机数据管理平台需求文档

V1.4 · 2026-11-06 · 工作组、申请审批及数据库指南同步版

本版依据用户确认的工作组和申请审批规则，以及最新[数据库设计指南](../database/database_design_guide.md)，替代需求 V1.3 中冲突的区域、项目授权和现场记录规则，配套[数据库设计 V1.5](../database/wildlife_database_design_v1_5.md)。[Word V1.4](platform-requirements-v1_4.docx)与本文同源生成，V1.3 及原始资料保留归档。

工作组是数据归属和人员授权单位。项目继承工作组权限，一期不设项目级授权；管理身份由系统管理员授予，工作、只读申请由工作组管理员审批。同步生境观察、相机参数、精确坐标与数据下载权限、多段有效工作等指南更新。本文描述目标能力，不表示程序或运行数据库已经实现。

## 1. 项目目标与业务逻辑

面向多个工作组的野生动物监测，以红外相机影像为基础，统一组织位点、维护与布设周期、NAS 影像、物种标签、豹个体标签及长期档案，形成可查询、可追溯的数据链路。二期扩展人工个体标注、繁殖记录、可视化与报告。

[既有业务逻辑与功能分期图](platform-business-framework-v1_3.png)

既有业务图保留九模块及功能分期；数据归属、权限、维护和一期档案范围以本版正文为准，图件中的旧术语不作为新权限规则。

核心链路：相机管理 → 影像文件管理 → 物种标签导入 → 个体标签导入 → 个体档案管理 → 数据查询与统计。位点、维护、影像和物种数据可直接进入查询统计；二期个体标注工具与一期导入共用个体数据，繁殖记录及报告沿用该基础。素材库从影像管理扩展，建设时间待定。

## 2. 功能模块与分期

| 序号 | 功能模块 | 一期 | 二期 / 后续 |
|---|---|---|---|
| 1 | 相机管理 | 位点信息、生境调查、操作记录、布设周期；按工作组管理 | 按后续业务需要扩展 |
| 2 | 影像文件管理 | 统一管理 NAS 等存储中的影像，关联位点、时间、物种和个体 | 持续复用 |
| 3 | 素材库管理 | 不纳入一期验收 | 待定：分类管理素材图片、视频，关联物种和个体 |
| 4 | 物种识别 | 仅导入已有物种标签，沿用 XMP | 后续可扩展 AI 识别与人工复核，具体阶段另定 |
| 5 | 个体识别 | 仅导入已有个体标签，沿用 Excel | 二期开发人工个体标注工具，优先于新增物种识别工具 |
| 6 | 豹个体档案管理 | 编号、性别、出生年份、多角度身份照及拍摄记录；一期不含个体关系 | 持续复用 |
| 7 | 豹繁殖记录 | 不纳入一期验收 | 二期：母豹与幼崽编号、出生日期和位点、幼崽存续情况 |
| 8 | 数据查询与统计 | 各工作组位点与回收情况、物种拍摄记录及 RAI、豹分布位点和个体出现记录 | 承接二期繁殖等数据 |
| 9 | 可视化与报告导出 | 不纳入一期验收 | 二期：豹个体家域及动态变化、物种分布动态、模板报告 |

物种 AI 识别是后续可扩展方向，不承诺在二期交付；不因此增加一期 AI 服务。二期人工个体标注工具优先开发，是因为个体识别现有工具化程度较低。素材库不自动归入二期。

一期同时包括账号注册、工作组申请审批、成员与项目管理、精确坐标和下载控制，不因九项业务模块表未单列系统管理而遗漏。

## 3. 一期详细要求

### 3.1 模块1-相机管理

work_group 是数据归属和人员权限管理单位，指南业务名 group，不等同于行政地理区域。固定工作组配置由系统管理员维护；项目和位点分别属于一个工作组，位点可关联本组多个项目，不能跨工作组关联。一个位点的机位、维护、周期、媒体与标签共用一份事实，跨项目统计去重。

位点信息增加非必填的网格编号，按文本保存并保留前导零；表单中放在小地名之后、关联项目之前。

位点保存相对稳定的位置、经纬度、海拔、生境类型和地形等基础信息；编号在工作组内唯一。布设类型及启用状态由相机操作记录动态推导，停用不释放编号或删除历史。生境、地形等少量固定选项直接作为字段，通过统一配置和数据库 CHECK 校验，不为每个字段建字典表。

布设类型和位点启用状态是随时间变化的只读计算结果，不手填，也不固定在布设周期内。按查询时刻每个机位最后一条已知操作后的在位标记汇总：0 台为无布设/停用，1 台为单侧/启用，2 台为对拍/启用。故障、关机、收卡换卡和更换实体设备不等于撤机；撤回或确认丢失且未补装时不在位，丢失后补装恢复在位。丢失日期未知时只在实际检查日期记录已知结果，不倒推未知历史。

维护记录 is_deployed_after 表示操作完成后是否有相机在位，与 working_status_after 和有效工作区间独立。历史按实际操作日期及同日顺序计算，不按录入时间、周期内累计相机数或 open 周期数计算。当前 DATE 模型查询所选日期最后一次操作后的状态；同日多次操作按 maintenance_sequence 排序，不伪造小时分钟。没有记录时按已记录事实计为 0 台，但缺失操作历史不构成已核实的现场停用结论；没有位点编号时不显示计算结论。超过两台保持启用，布设类型显示待核查。

新增 location_habitat，按观察日期记录会变化的植被信息、动物痕迹和人为干扰，保留历次调查，不覆盖旧记录。记录可关联同位点维护，观察人和录入账号区分；未调查不等于未发现。

camera 表示位点内机位而非实体设备。现场记录统一为操作记录（既有设计标识 maintenance），包含安装、检查、撤回三种类型，保存维护批次、日期、维护后的相机型号及参数、工作状态、异常和维护内容。型号和参数在周期起始时保存快照，不以新配置覆盖旧周期。参数字段和单位以真实模板确定。

deployment 保存两次边界维护之间的周期，首次从安装开始，允许开放或已结束。成功回收后继续布设时，同一维护既结束旧周期又开启新周期；空卡或文件损坏仍记确已取得数据，失败尝试不伪造成功回收。维护、布设及有效工作日期使用 DATE，同日多次维护明确顺序。

指南确认周期内故障后修复虽少但存在，使用 deployment_work_interval 保存多段实际有效工作区间。分母取已确认区间并集，不能用首末日期跨度计入停机时间；资料不足时不输出正式工作量。单纯故障恢复不伪造回收维护。

Excel 导入统一预校验、差异反馈和整批事务提交，提交时重验成员权限、唯一性及并发变更。模块1当前详细需求见 [相机管理 V2.0](module01-camera-management-v2_0.md)，旧模块文件仅供历史追溯；与旧模型冲突的四张表单和操作规则以当前模块需求为准。

### 3.2 影像文件管理

统一索引 NAS 或本地磁盘保存的原始视频及图片，支持批量入库、查询、筛选、鉴权浏览与播放。数据库保存文件路径、文件名、大小、哈希、格式和必要的媒体元数据，不把原始视频存入数据库。

影像通过布设周期关联机位、位点和工作组，并记录实际取得文件的维护来源；关联物种标签、个体出现记录及个体档案。媒体未完成标签导入时仍可查询和播放。拍摄时间沿用首次导入读取文件修改时间的既有规则，原值保留。默认采用周期统一有符号秒偏移；历史或特例单文件绝对校准值优先，不重复叠加。来源时区及 mtime 可靠性用真实样例验证。

原始影像保持不变；缩略图和浏览器代理视频属于媒体服务支撑能力，一期可按播放需要生成，不等同于素材库建设。播放和预览按成员读取权限鉴权，原始媒体下载、打包及业务导出另检下载权限；NAS 路径不直接公开。

### 3.3 物种标签导入

一期只导入平台外完成的物种识别结果。沿用 XMP 文件级标签，一个媒体可对应多个物种；不从标签推断动物数量、检测框或帧时段。保存标注人员、复核状态、复核人员和导入记录。

提供预校验、媒体匹配、失败反馈和更正追溯。匹配必须结合周期及目录上下文，不能仅按文件名。成功重导替换对应媒体的当前标签并保留前后快照；失败、歧义匹配及未知物种不得覆盖旧结果。空标签不默认清空已有标注。未来 AI 与人工复核的结果应经单独设计再接入同一有效标签层。

### 3.4 个体标签导入

一期仅通过 Excel 导入已有个体识别结果，模板包含媒体匹配信息、已确认个体编号或未知个体标签，以及标注与复核信息。支持一个媒体多个已确认个体，以及已知个体与未知个体同时存在。

同一媒体同一个体只保留一条当前有效出现记录。未知个体使用 `unknown_individual`，不建立虚拟个体档案，不据此推算未知个体数量或跨视频身份。导入完成状态沿用 `unannotated / annotated`；已标注不等于所有个体身份均已确认。

按“预校验 → 确认 → 提交”执行；重复相同结果幂等，变更结果明确显示差异并经操作者确认后按媒体替换。保留导入批次、逐媒体结果与前后快照，失败不得清除原结果。缺失档案应先补建或经明确建档步骤处理，不根据模糊编号静默新建。二期人工工具复用相同出现记录、完成状态及审计规则。

### 3.5 豹、兔狲等个体档案

一期包括当前和历史编号、物种、性别、出生年份及可选出生日期上下界、存活状态、多角度代表图和拍摄记录；一期不纳入个体关系。只知年份不伪造月日，未再观测到不等于确认死亡。个体内部 ID 稳定，改号保存旧号。

代表图独立于原始媒体，支持左侧、右侧、正面、背面、多角度，以及全身、脸、尾、各肢体部位；默认“多角度、全身”供拼合图导入，一个个体可有多张图及一张选定主图，主图必须属于自身。

档案归属工作组，成员按本组权限使用；跨组身份对照和代表图共享未定义前不自动开放。历史跨组关联由系统管理员核对，不静默复制、删除或合并身份。拍摄记录由媒体关联计算，工作组成员不能获得其他组首末拍或地点汇总。

### 3.6 数据查询与统计

| 主题 | 一期结果 | 数据来源与口径 |
|---|---|---|
| 位点与回收 | 按工作组、项目、位点、维护批次筛选维护与布设情况 | 按维护 ID 去重并区分类型；数据取得比例注明分子分母及范围，不冒充计划完成率；无分母不可计算 |
| 物种拍摄 | 按物种、工作组、时间、位点和批次查询影像记录 | 明确“媒体文件数”口径；多物种媒体可计入各物种，合计不等于唯一媒体数 |
| 物种 RAI | 按选定范围计算相对多度指数 | 物种独立拍摄次数 / 有效相机工作日 × 100；展示独立判定及多段工作量口径 |
| 豹分布位点 | 查询豹物种出现位点 | 来自豹物种标签，包含尚未确认个体身份的影像；不限定为已建档个体的出现 |
| 豹个体出现 | 按编号、工作组、时间、位点查询已确认个体的出现记录 | 来自个体出现记录，未知个体标签不计作独立个体 |

RAI 的独立拍摄间隔、按位点还是按相机去重、对拍处理和有效工作日计算方法须在详细统计设计时确认，不能默认为已获业务认可的固定参数。布设跨度和有效工作首末日期范围不能自动等于有效工作日；缺少可靠工作量、时间或规则时，显示“不可计算/资料不完整”，不把缺失值填零或输出伪精确数值。参数齐备时应可复现计算范围、版本和结果。

一期不建独立事件及成员表，使用 media 的文件级独立标记和 media_species 的物种级标记；多物种各自判定，NULL 表示未判定。时间、物种标签或规则更改须重算，筛选排除原代表文件或改变候选集合时在范围内临时重算，不能直接累加旧标记。

一期交付查询列表与统计结果；家域图、时空动态展示和模板报告归二期。模块 01 的错误表、导入结果反馈不因“报告导出属二期”而取消。

## 4. 二期要求及待定模块

### 4.1 人工个体标注工具

支持观看视频、检索既有档案与历史影像、比对身份照/花纹、手工确认或标记未知、复核及纠错。结果直接写入与一期 Excel 导入共用的有效记录层，并保存来源与审计；不另建孤立的个体身份体系。二期此工具不要求 AI 个体识别。

### 4.2 豹繁殖记录

按繁殖事件管理母豹、幼崽编号、已知或估计的出生日期、出生位点及影像证据。不同幼崽分别保存身份、独立及存续情况；未再观察到不等于确认死亡。幼崽独立改号沿用同一个体 ID。父豹、推测区间、观察数量等既有可选字段可保留，不变为强制填写。

### 4.3 可视化与报告导出

查看豹个体家域及动态变化、物种分布动态，按模板生成报告。家域估计必须说明数据范围、算法、参数与不确定性；相机离散探测点不能直接表示连续活动轨迹。MCP/KDE 等方法及报告模板、导出格式在二期详细设计中确定；统计结果、坐标和导出文件均受权限约束。

### 4.4 素材库管理（待定）

分类管理精选图片、视频，关联物种与个体。素材选编、裁剪、分类及发布流程待单独设计；当前只保留可复用媒体及标签的扩展边界，不承诺一期或二期交付。系统未知个体标签和档案身份照仍属一期必要数据。

## 5. 数据归属、注册和权限

### 5.1 两类账号、三档工作组身份

账号表区分 system_admin（系统管理员）和 normal（普通用户）。普通用户可加入多个工作组，在各组分别具有 manage（管理）、work（工作）、read（只读）身份；身份放在用户—工作组成员关联中，不放入账号类型。

项目继承工作组权限，一期无项目级单独授权。成员能访问本组全部项目及未挂项目的位点，项目筛选不产生或取消权限。工作组关联和数据归属通过稳定 ID 表达，不能依赖名称字符串。

### 5.2 注册与申请审批

自助注册固定创建普通账号。注册者可申请加入一个或多个启用工作组并选择等级，各组独立提交、审批；未获批时只能查看本人申请和必要账户信息，不得读取组内业务数据。已有成员可再次申请调整等级，待审期间保留原已批准权限。

| 申请类型 | 审批者 | 通过后的结果 |
| --- | --- | --- |
| 加入或调整为工作、只读 | 本组管理员或系统管理员 | 创建或调整该组有效成员 |
| 申请管理，或调整现有管理身份 | 仅系统管理员 | 任命或调整工作组管理员 |

状态为待审、通过、拒绝、撤回。待审申请可由本人撤回，拒绝说明原因；已办结记录保留，重新申请使用新记录。同用户同组只允许一条待审申请。审批者不能自审，提交结果前验证当前资格和并发成员版本。

审批通过、成员授权和审计同一事务；重复审批不重复授权。拒绝、撤回不创建成员、不清除已有有效权限。系统管理员可直接任命首位组管理员并保留审计。工作组管理员不能任命同级管理员、修改自身管理身份或提升为系统管理员。

### 5.3 能力边界

| 身份 | 本组能力 |
| --- | --- |
| 只读 | 查询、播放、预览、查看统计；不能修改业务数据 |
| 工作 | 只读能力，加维护位点/生境/机位/维护/周期/校准、媒体及标签导入、个体档案维护 |
| 管理 | 工作能力，加项目及关联管理、工作/只读成员审批和管理、删除未引用的误建业务数据 |
| 系统管理员 | 全系统管理、固定工作组配置、管理身份任命和全局字典维护 |

被业务引用的数据禁止直接删除。项目负责人不自动获得权限；工作或只读不能转授权。账号停用影响全部组，成员停用只影响所属组；撤权后旧会话、文件链接和导出任务必须复验权限。

### 5.4 精确坐标与下载

按工作组成员保存精确坐标、数据下载两个附加开关，不按项目分别配置。系统管理员和本组管理可查看坐标及下载；工作成员可查看坐标，下载另需开启；只读成员的坐标和下载均按开关。

下载包括原始文件、打包及业务数据导出，不等同于预览播放。允许下载仍不能导出无权坐标；轨迹原文件同时要求坐标和下载能力。创建、执行及领取导出结果时均复验权限，后台任务不持有永久访问权。导入反馈、统计快照和审计同样过滤组外资料和无权坐标。

### 5.5 数据架构与审计

PostgreSQL + PostGIS；基础链为 work_group → location → camera → camera_deployment → media，项目通过 project_location 关联位点；维护独立留记录，物种和个体由 media_species、media_individual 关联。生境观察和有效工作区间分别关联位点、周期。物种为全局字典；个体档案按归属工作组隔离。

注册、申请、审批、撤权、资料变更、导入覆盖、改号、校准、下载及后续繁殖修改保留审计；业务与成功审计同事务。生产数据和文件定期备份，NAS 不直接公开。工作组代码或项目筛选参数不能代替后端鉴权。

## 6. 技术与部署

前端 React + TypeScript，后端 FastAPI，数据库 PostgreSQL + PostGIS，影像存于 NAS/磁盘，按需 FFmpeg 生成播放代理。Docker Compose 部署至 Dell Windows 11 + WSL2；GitHub 管理代码与文档，自动检查和真实数据验收分别执行。未来 AI 方向不改变一期无 AI 服务的部署边界。

## 7. 分期验收

一期闭环：注册普通账号 → 申请工作组及等级 → 按等级由有资格人员审批 → 维护本组项目、位点、生境、机位、维护、参数及布设 → 入库并播放媒体 → 导入 XMP 物种和 Excel 个体标签 → 维护档案、历史编号和多角度代表图 → 查询及计算可复现统计。故障恢复有两段以上有效工作时不计入停机跨度；资料不足时准确提示不可计算。

验收须覆盖：未审批无数据访问权、同用户多组不同等级、工作组管理员不能批准管理身份、自审与重复/并发审批被控制、待审升级不预先生效、撤权后旧文件及导出任务失效、项目完全继承、跨组请求被拒绝、只读下载坐标脱敏、生境历史不覆盖、维护后参数快照正确、物种独立标记不被文件级标记误过滤。

二期闭环：人工个体标注及复核、繁殖事件和幼崽存续、家域/分布动态及模板报告。素材库和物种 AI 不作为二期必验功能。
