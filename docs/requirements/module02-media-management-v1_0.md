# 模块2—影像文件管理需求

V1.0 · 当前审阅范围：回收批次目录关联、媒体索引和周期时间校准。

依据：[总体需求 V1.4](platform-requirements-v1_4.md) 3.2、用户维护的[数据库 guide](../database/database_design_guide.md)、[使用场景](../design/scenario.md) 2–3，以及本次对话确认的回收后拷贝和时间校准流程。本文维护需求，不表示正式服务已实现；演示范围见 [Demo README](../demos/module02/README.md)。

## 用户路径

进入影像文件管理 → 默认查看批次媒体目录及处理状态 → 关联已拷贝的批次文件夹 → 核对位点、相机、布设周期、文件数量与存储位置 → 确认建立索引 → 打开目录查看文件 → 按周期规则预览并写入校准时间。关闭、取消或保存后回到原列表上下文；完成目录关联后可定位到对应批次。

默认以相机目录呈现归属摘要，不把所有媒体文件同时展开。点击整行或键盘 Enter/空格打开只读详情；校准有明确入口，不把查看默认变成编辑。完整文件在详情中分页，路径可复制，清单按当前筛选范围导出。

## 已确认规则

- SD 卡先回办公室，由用户将媒体拷贝到电脑/NAS；路径按“回收批次 / 位点编号 / 相机编号 / 媒体文件”组织。关联建立路径索引，不重新上传或改写原始影像。
- 归属链为工作组 → 位点 → 机位 → 布设周期 → 媒体。批次是回收维护来源，不替代周期 ID。目录与周期的对应关系需核对；不以文件名或时间接近就静默认定归属。
- 布设周期来自相机管理的操作记录；媒体模块不新增周期或修改其起止日期。周期闭合不等于已取得文件；未关联目录不等同于空卡、丢失或损坏。
- 首次扫描读取文件修改时间作为原始拍摄时间，后续校准保留该原值。时间按北京时间 UTC+8 显示，导出保留带时区的时间点。mtime 在拷贝后的可靠性及来源时区仍须真实样例验证。
- 时间校准沿用相机管理规则：填写首条视频的相机时间和对应实际时间，差值为该周期统一有符号秒偏移。已有规则可带入；没有依据时不根据周期首末日期自动推导偏差。
- 校准时间 = 原始拍摄时间 + 周期偏移。对周期内全部已关联媒体统一应用，再次校准从原值重算，不在上一次结果上重复叠加。历史/特例单文件绝对校准值优先。
- 周期日期范围检查用于发现异常，不自动删除媒体或改变其周期归属。周期外文件仍按同周期规则校准并保留异常提示，供进一步核查。
- 统计分别显示相机目录数、媒体文件数及视频/图片数，不将文件数称作独立拍摄次数或有效工作日。
- 只读查看与业务写入、下载分开；正式权限继承工作组身份及下载开关。浏览器演示不代表真实鉴权完成。

## 预检和操作反馈

关联前显示扫描数量、文件修改时间及目录—周期匹配结果。无法确定周期、路径层级错误或已有路径信息冲突时阻止提交并定位问题；不得覆盖首次记录的修改时间。确认后保留成功数量和重复跳过数量，失败不显示成功或清空输入。

列表支持批次、处理状态、位点/相机/路径关键词的组合筛选，变化回第一页；默认每页 10 个目录，重置清空条件。区分无记录、筛选无结果、待校准、已校准、时间待核查和周期待核对。关闭详情保留筛选与分页。

## 本轮范围与待设计

本轮只实现目录索引及校准闭环。真实鉴权、NAS 服务、哈希、代理播放、识别关联及后台批量任务继续按总体需求推进；不因本轮完成而认定整个一期媒体模块验收完成。

同路径同大小/mtime 的重复跳过、输入偏差不超过一年的校验及浏览器存储是演示实现选择，不是正式业务契约。正式防重需结合受控存储、稳定媒体 ID 和哈希；同相机同批次多次回收须按真实周期和维护来源核对。

布设边界目前是日期。日期外可判异常，同一维护日内文件到底属于前/后周期不能仅靠日期解决；有歧义时需人工核对，正式接口不得伪造时分秒。周期故障、多段有效工作量和归属更正另行设计，不能从本轮媒体首末时间直接推导。

本模块新校准记录与相机管理台账的双向一致性、并发修改/追溯、单文件特例的维护入口和媒体服务写入事务待正式接口设计；当前 Demo 不自动改写另一模块台账或源文件。

## 建议同步到 guide

本次用户已确认的回收后处理场景尚未逐项进入 guide，建议补充：每个回收批次完成后关联“批次—位点—相机—文件”的实际存储目录，按已结束布设周期核对归属及媒体数量；首次读取修改时间作为原始拍摄时间，周期校准统一生成独立校准时间，保留原值和异常记录。本文不直接修改用户维护的 guide。
