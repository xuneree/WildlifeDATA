# 模块1-相机管理

版本：V2.0 · 2026-11-10。状态：当前模块设计与后续工作基线。

模块代码为 `module01`，对外统一称“模块1-相机管理”。包含位点信息、生境调查、操作记录、布设周期；“操作记录”记录相机现场操作，不等同于系统审计日志。其他模块编号及分期沿用总体需求，本次不重新命名。

## 依据与范围

依据用户本次确认的模块范围、[数据库 guide](../database/database_design_guide.md)、[使用场景](../design/scenario.md)和最新表单源码 `cf224c9b4cb95c3252332b92bddebb2ae74d7e78`（PR #4）。本版替代旧模块的位点与回收需求及低保真交互稿；[旧资料完整归档](../archive/module01-legacy/README.md)。已确认新规则优先于旧 guide 的冲突描述，guide 由用户维护。

目标闭环：建立位点 → 按需调查生境 → 记录安装/检查/撤回 → 核对布设周期、故障与时间校准 → 为媒体归属和后续统计提供依据。当前 Demo 是独立浏览器原型，正式前端、后端及迁移仍待实现。

## 四个页面的当前规则

通用：桌面四栏、平板两栏、手机单栏；使用轻量分区。工作组从全局上下文带入，不在表单中填写。未填输入和未选下拉显示为空。不设历史补录模式，所有表单统一按字段及条件校验；可选项允许留空。

### 位点信息

| 分区 | 字段顺序与交互 |
| --- | --- |
| 布设信息 | 位点编号、区域、小地名、网格编号、关联项目；设置人员、首次布设日期 |
| 在位状态 | 状态日期、在位相机数、布设类型、位点状态；后三项只读，由已保存操作自动计算 |
| 别名 | 位点编号下方显示“别名：添加”；填写后为“别名：xxx 修改”，添加和修改是文字链 |
| 地理信息 | 经度、纬度、海拔、生境类型；地形位置、坡向、坡度、水源位置；不展示其他生境说明 |
| 现场资料 | KML 轨迹、位点照片、备注；两类文件各最多 10 个，可逐项删除，照片有缩略图 |
| 生境调查 | 当前位点的调查历史与新增入口；打开历史后可修改、删除 |

位点编号在工作组内唯一是业务约束，正式接入需由后端保证。网格编号为非必填文本，放在小地名后、关联项目前，允许字母及前导零；项目下拉多选且选填；布设类型和位点状态取消手填及默认值，由记录推导；水源位置为 ≤100 m／＞100 m。当前原型不实现跨工作组真实权限校验。

### 位点在位状态

- 0 台无布设/停用，1 台单侧/启用，2 台对拍/启用；故障或关机仍算在位。超过两台保持启用，布设类型显示待核查。
- 按工作组、位点、机位分组，取查询日期及此前最后一条操作的 `is_deployed_after`。安装为在位；检查依据操作后的实际结果，故障、收卡换卡或换机不减少在位数量；撤回为不在位。丢失且未补装为不在位，丢失后补装为在位，未知丢失日期不向前推断。
- 当前原型沿用日期精度，显示所选日期最后一次操作后的状态，同机同日按记录顺序处理。补录按操作日期排序；同机反复检查不重复计数，未来记录不影响当前，周期结束或数据回收不等于撤机。
- 操作保存到独立浏览器历史，不依赖最后一份表单草稿；重复保存同一记录更新原记录。刷新后恢复，JSON 导出包含 `operation_records` 和带查询日期的 `location_state`，位点基础数据不再导出手填 `loc_type`/`loc_status`。草稿里的旧手填状态被忽略。
- 没有位点编号时不显示结论；没有操作记录时按已录入事实计算为 0。旧版本的草稿、工作周期和静态设备示例不自动当作在位事实，已有位点须补录真实操作历史。历史资料缺失不等于现场已核实停用。

### 生境调查

- 基本信息：位点、调查日期、调查人员。按需独立调查，不与相机操作强制绑定。
- 植被信息、动物痕迹、人为干扰各有一个“未调查”，放在分区标题右侧；未调查的内容不参与必填并导出为空。
- 植被包括乔木高度／郁闭度、森林起源、灌木高度／盖度、草本类型／盖度。不增加树种胸径样本。
- 动物痕迹默认一条空记录，物种名称与痕迹类型为 1:3；完全空白行不导出为发现记录，部分填写须补全。
- 痕迹：实体、粪便、食迹、足迹、卧穴、爪痕、蹭痕、毛发、尸体。干扰：放牧、套子、电网、车辆、偷树、砍树、旅游、采药、其他。

### 操作记录

基本字段：位点、相机编号、操作批次、操作日期、操作类型、操作人员、记录人员。

**操作批次选填**：点击输入框展示当前工作组最近批次，可直接选入，也可自由输入；不做编号格式校验。

| 类型 | 表单表现 | 周期结果 |
| --- | --- | --- |
| 安装 | 型号和条形码空白填写，参数取默认值；不填操作前状态或操作内容 | 开启周期 |
| 检查 | 带入上一次相机信息，默认只读；下方填写相机状态、操作内容；备注放在操作内容中 | 结束上一周期并开启下一周期 |
| 撤回 | 带入只读相机信息，填写现场状态及撤回原因；不填写操作内容 | 结束当前周期 |

相机信息保留必要的上次记录日期。拍摄模式、时长（照片时为连拍张数）、时间间隔、灵敏度在同一排。默认照片 1 张、视频 15 秒、间隔 10 分钟、灵敏度中。

检查的操作内容为：收卡换卡、更换电池、更换相机、丢失后补装、调整参数、其他。更换相机／丢失后补装允许修改型号与条形码；调整参数允许修改拍摄参数；取消选择后恢复上次值。旧回收／更换草稿转为检查，旧停用转为撤回，保留已有说明与实际动作。

### 布设周期

- 字段：位点、相机编号、布设开始日期、回收日期。不填型号、判断依据、确认人或完整核实确认框。
- 默认选择“无故障时间”；选择“有故障时间”后展开一条填写行，可添加多段。故障开始日期、恢复日期、故障说明为 1:1:2。
- 故障段须位于周期内且互不重叠；日期区间沿用原型的 `[开始日, 结束日)` 约定。
- 时间校准始终可填，无故障也可只校准：输入首条视频的相机时间和实际时间，自动计算本周期加减秒数。时间按北京时间 UTC+8 解释。
- 保存现场正常的相机操作后，内部保留周期关联与记录逻辑，界面不展示自动确认提示；已有故障事实不会因后续现场正常被清空。
- 日志记录当前演示账号 `demo-user`，正式接入需替换为登录账号。周期记录、审计和草稿均仅保存在当前浏览器。


## 正式实现边界

- 数据归属工作组，项目继承工作组权限；位点可关联本组多个项目，项目选填。机位、调查、操作、周期应采用稳定 ID 关联，不依赖名称或日期文本匹配。
- 工作与管理身份可维护本组业务；只读不能写入。精确坐标、轨迹、下载和审计按总体需求权限控制，后端每次验证，原型示例账号不代表真实权限。
- 修改业务及成功审计同事务；保存失败保留输入，不写部分记录。业务引用保护、并发校验及日志账号由正式接口实现。
- Excel 批量导入仍属一期需求：预校验、差异反馈、整批事务提交、提交时复验权限与并发；当前四表单 Demo 未实现该能力。旧归档模板不再作为当前模板，四类数据模板及映射另行设计。
- 无记录的在位数量 0 只是已记录事实，不能作为现场已核实停用的证据。资料不足时不输出正式有效工作量；故障多段区间与“未完整核实不按首末跨度统计”原则的正式核实流程仍待衔接。界面不重新增加已取消的人工确认字段。
- 媒体入库、播放、物种/个体标注和生态统计由对应模块实现；本模块不新增实体相机库存或项目级授权。
