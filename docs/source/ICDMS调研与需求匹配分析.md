# ICDMS 工具调研 与 数据管理平台 v1.3 需求匹配分析

> 调研对象：LinkDatasets 的 ICDMS（ICDFactory + ICDManager）  
> 对照基线：WildlifeDATA `docs/requirements/platform-requirements-v1_3.md`  
> 调研方式：登录后阅读两份官方使用手册正文（ICDFactory 使用手册 / ICDManager 使用手册）

---

## 一、ICDMS 是什么

ICDMS 是面向**野生动物红外相机监测**的商业化「软硬件一体数据管理方案」，由 LinkDatasets 团队提供。整套产品包含三个子产品，本次调研覆盖其中两个：

| 子产品            | 形态            | 定位              | 一句话                         |
| -------------- | ------------- | --------------- | --------------------------- |
| **ICDFactory** | Windows 桌面客户端 | 数据标准化 + 识别 + 标注 | 把 SD 卡原始影像变成「已校对、可导出」的标准数据集 |
| **ICDManager** | Web 平台        | 数据管理 + 可视化 + 分析 | 在云端聚合查看点位、媒体、统计看板、申请处理      |
| ICDWeb         | Web（未调研）      | —               | 第三款产品，本次不涉及                 |

**部署与账号模型（关键）**：

- ICDFactory 是 Windows 10+ 桌面软件，识别推理模块约 3GB，客户端约 160MB，模型训练需 NVIDIA GPU 显存 ≥ 6GB。
- 依赖云端：需在官网注册账号 + 邮箱验证，桌面端登录时未开通账号会弹「申请表单」，**审核通过后才能使用**；识别/训练/部分 AI 功能走云端服务（手册明确「建议不要开 VPN，否则服务器响应变慢」）。
- 数据/路径约束：软件文件夹路径与 ICD 数据集名称**严禁中文**，仅限英文、数字、下划线。
- 部分 AI 功能需单独申请 API KEY（`lcdms_llm_` 开头）并**消耗账户余额**。

## 二、ICDFactory 功能清单（手册已证实）

### 2.1 核心处理链路

完整操作流程（手册 3.3）：

```
新建 ICDset → 数据导入(读取布设) → 自动识别 → 人工校对与标注 → 全局校对/导出
```

### 2.2 功能明细

| 模块               | 手册证实的能力                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **ICDset 管理**    | 创建/删除数据集；「外源 ICDset」可引入其他路径下 ICDFactory 整理的数据集，适合多人协作交付                                                                         |
| **数据导入（读取布设）**   | 在文件系统把布设文件夹命名为「点位编号+回收日期」（如 `TJHs1+2024-02-13`）→ 批量添加 → 读取；实时显示磁盘空间                                                             |
| **点位生境信息**       | 经纬度必填；可自定义字段（海拔、植被类型、坡度、坡向、水源距离、乔木/灌木优势种等）                                                                                      |
| **点位布设信息**       | 布设状态用颜色标识：黑色=未处理、红色=已识别未校对、绿色=已校对；可删除布设                                                                                         |
| **自动识别任务**       | 拖拽布设进识别队列→选模型→后台识别；官方提供中国西部/东北地区常见物种识别模型；**支持外部识别模块接入**（定义好输入输出入口即可，有接口文档）                                                      |
| **人工校对与精细化标注**   | 物种标签（输入中文名自动匹配物种+IUCN 等级）；空拍/干扰/自定义标签；分组筛选+分组核对（连拍一组批量标注）；**个体信息标注**（点击「查看」进入编辑模式，逐个体编辑）；固定标签、影像缩放、高清原图、视频倍速(0.5/1/2/4X)、另存为、删除 |
| **全局校对、数据导出与分析** | 动物数据表/生境数据表；批量修改物种/数量/备注；列筛选；月相自动计算；**「独立有效记录」算法**（按位点+拍摄时间+物种+时间间隔去重）；批量替换物种名；精选媒体；**导出元数据(.xlsx/.csv)+源文件**                   |
| **自主模型训练**       | 用已校对+已框选目标标注的照片，调用 ICDRec 训练**物种识别**模型；支持合并本地+外源 ICDSet；「自动识别—人工复核—再训练」迭代                                                       |
| **AI 功能（LLM）**   | 物种名称标准化（俗名/旧名/学名检索）、目标框选（可编辑边界框，含小目标模式）、视频行为识别、视频抽帧、时间与温度提取、行为谱构建、数据脱敏                                                          |

## 四、与 v1.3 需求逐项匹配

### 4.1 总体结论

**ICDMS 是一个成熟的「红外相机数据生产/标注/可视化」工具，与你「自建数据管理平台」在业务领域上高度重合，但在产品定位、数据架构、权限审计和导入方向上存在根本性差异。**

核心矛盾：你的平台&#x662F;**「自建、可查询、可审计、开放数据模型（PostgreSQL+PostGIS）」的管理系统**；ICDMS &#x662F;**「封闭、云端依赖、私有数据集格式（ICDset）」的加工工具**。ICDMS 强在「识别与标注」这一环，弱在「档案管理、精细权限、可复现统计、开放集成」。

### 4.2 需求匹配明细

| v1.3 模块                 | 匹配度                      | 说明                                                                                                                             |
| ----------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| **1. 位点与回收记录**          | ⚠️ 部分满足                  | 有「点位+生境信息+布设」，但**无「工作与回收周期」正式数据模型**：无回收批次唯一性、回收率统计（分子/分母）、对拍计数、Excel 批量导入纠错、审计。导入靠文件夹命名约定，非结构化表单                               |
| **2. 影像文件管理**           | ✅ 基本满足                   | 批量入库、查询筛选、播放（倍速/原图）、预览、另存为均有；但「哈希/大小/格式元数据索引、后端鉴权浏览、代理视频」未见手册证实，且数据在私有 ICDset 而非可 SQL 查询的库表                                    |
| **3. 物种标签导入（沿用 XMP）**   | ⚠️ 工具内识别可替代，但历史标签导入无直接功能 | 若改用 ICDMS，可「在工具内自动识别+人工校对」完成物种标签，与「导入外部标签」不冲突。但**历史 XMP/第三方物种标签无法直接导入**：手册无 XMP 导入功能，唯一间接途径是「外源 ICDset」（且必须是 ICDFactory 整理的格式） |
| **4. 个体标签导入（沿用 Excel）** | ⚠️ 同上                    | 个体信息可在 ICDFactory 内**手工逐个体标注**（含性别/年龄/行为/动作描述字段），但**历史 Excel 个体识别结果无法直接导入**；无 Excel 导入模板、预校验/幂等/快照/替换语义                        |
| **5. 豹个体档案**            | ❌ 大部分不满足                 | 有「个体信息标注」（个体编号），但**无亲缘关系、历史编号、改号、出生年份（含只知年份）、身份照代表图、拍摄记录汇总**这些档案字段；个体只是标注结果，不是独立档案实体                                           |
| **6. 数据查询与统计**          | ⚠️ 部分满足                  | 有 RAI（物种相对多度柱状图）、物种累计曲线、独立有效记录算法等；但**统计口径不可自定义/不可复现**（事件合并规则、工作日口径、参数版本无法指定），无「豹分布位点」「个体出现记录」专用查询，无「资料不足→不可计算」的严谨缺失处理语义        |
| **7. 二期·人工个体标注工具**      | ✅ 较强                     | ICDFactory 的人工校对+个体信息标注+视频倍速/原图/固定标签，正是这类工具；甚至更完善（分组核对、小目标框选）                                                                  |
| **8. 二期·豹繁殖记录**         | ❌ 无                      | 手册无繁殖事件、母豹/幼崽编号、出生日期位点、幼崽存续管理                                                                                                  |
| **9. 二期·可视化与报告**        | ⚠️ 部分满足                  | 有统计看板 7 类图 + 地图，但**无家域估计（MCP/KDE 及其不确定性说明）、物种分布动态、模板报告导出**                                                                     |
| 10. 素材库管理（待定）           | —                        | 不在双方范围                                                                                                                         |
| **11. 数据架构与权限（横切）**     | ❌ 关键缺口                   | 无 PostgreSQL+PostGIS；无「管理员/区域工作人员/只读」角色模型、**区域级数据权限、坐标脱敏授权、审计日志、业务写入与审计同事务**；仅账号申请审核，不能满足精细权限与跨区域保密要求                          |
| **12. 技术与部署（横切）**       | ❌ 不满足                    | 非 React+FastAPI+PostGIS 自建；封闭桌面+云端、依赖官方服务器、账号审核制；无法 GitHub 管理、无法按你的数据模型扩展、无法与 tiger_annotator 等自研工具直接集成                        |

### 4.3 关键差异点（决定「能否直接采用」）

1. **数据主权与开放性**：ICDset 是私有格式，元数据只能导出 .xlsx/.csv；你的平台要求 PostgreSQL+PostGIS 直接可查询、可复现统计、可审计。**这是不可调和的架构差异**。
2. **导入 vs 生产**：你要的是「只导入外部已完成标签（XMP/Excel）」，ICDMS 要你在它内部完成识别+标注。若采用 ICDMS，等于重做一遍标注生产流程，且你的 OSNet 个体识别、v5~v9 数据集、PK Sampling 等既有资产无法直接进入。
3. **个体识别（ReID）**：ICDMS 的 AI 是**物种识别**（+目标框选），个体身份是**人工标注**；其「外部识别模块接口」理论上可接你的 OSNet 东北虎个体识别模型，但需按它的输入输出入口适配，属二次开发，手册未保证个体 ReID 场景。
4. **权限/审计**：你的需求对区域权限、坐标授权、审计、事务性导入有硬性验收标准，ICDMS 手册完全没有证据支持。
5. **成本与合规**：账号申请审核制、云端依赖、LLM 功能按余额计费、数据可能上云——与你「本地自建、GitHub 管理、NAS 不直接公开」的部署边界冲突。

## 五、结论与建议

**结论：ICDMS 不适合直接作为你的数据管理平台，也不适合作为其替代品。**

- **可直接借鉴/满足**：影像入库与播放、人工标注交互设计（视频倍速、原图、固定标签、分组核对）、独立有效记录/RAI 的统计思路、聚合地图与统计看板的可视化形态。
- **无法满足（且是硬性验收项）**：位点-回收周期正式模型、XMP/Excel 标签导入语义、豹个体档案（亲缘/改号/出生年份/繁殖）、区域级权限+坐标授权+审计、PostgreSQL+PostGIS 开放数据架构与可复现统计、自建部署与自研工具集成。

**建议路径**：

1. 继续按 v1.3 自建平台（PostgreSQL+PostGIS + FastAPI + React），保持数据主权与开放查询能力。
2. 把 ICDMS 当作**参考对象**而非底座：借鉴其标注交互与统计看板设计，落到你自己的平台 UI 上。
3. 若看中其「外部识别模块接口」与「LLM 目标框选/物种名标准化」，可作为**可选的能力供应商**单独评估接入，但需确认接口、数据流向、成本与合规。
4. 你的 OSNet 东北虎个体识别、tiger_annotator、多版本数据集资产，只能在自建平台上完整承载——ICDMS 无法承接这部分。

## 六、常见疑问澄清（本地/云端、标签导入、费用）

### 6.1 本地功能 vs 云端功能

| 归属                     | 功能                                                                                                                                     | 依据                           |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| **本地（ICDFactory 桌面端）** | 数据导入（读取布设，读本地 NAS/磁盘）、自动识别推理（识别推理模块约 3GB 本地下载、后台独立进程）、人工校对与标注、自主模型训练（本地 NVIDIA GPU ≥6GB + ICDRec）、全局校对/导出（本地导出 .xlsx/.csv）、ICDset 数据存储 | 手册 2.1/3.3/4.5/4.8 证实        |
| **云端（需联网）**            | 账号注册/登录/申请审核、识别模块下载、**LLM 类 AI 功能**（物种名标准化、目标框选、视频行为识别、视频抽帧、时间温度提取、行为谱构建、数据脱敏，需 API KEY 且消耗余额）、ICDManager 的 Web 地图/汇总表格/统计看板、ICDWeb 门户 | 手册 1.4/4.9 + ICDManager 手册证实 |
| **需厂商确认**              | 自动识别是否可完全离线（手册「后台独立进程+本地模块」倾向本地，但模型下载/授权校验可能走云端）；ICDManager 云端预览用「全量影像」还是「代理/缩略图」                                                      | 手册未明确                        |

手册 1.4 明确「建议不要开 VPN，否则服务器响应变慢」，说明客户端与官方服务器存在持续通信。

### 6.2 在线标注 / 影像上传

- **在线（网页）标注：不支持。** 人工校对标注只在 ICDFactory **桌面客户端**完成；ICDManager 是 Web（数据管理/地图/看板/申请审批，仅「预览/另存为」无标注）；ICDWeb 是浏览器门户（模型广场/开发文档/参考文献/账号），均无标注能力。
- **影像是否上传云端**：纯 ICDFactory 流程（导入→识别→标注→导出）**在本地完成，无需上传原始影像**。但要使用 ICDManager 的云端地图/看板/媒体预览与「数据协作申请与审核」，则数据（至少元数据+缩略图/代理）需同步到云端——**全量还是代理，手册未说明，需向厂商确认**。

### 6.3 历史识别标签能否导入

- 手册**未提供「导入第三方历史标签（XMP 物种 / Excel 个体）」的直接功能**。
- 唯一间接途径是「**外源 ICDset**」：可引入其他路径下「由 ICDFactory 整理的数据集」（含其标签），适合多人协作——即历史标签必须已转成 ICDFactory 的 ICDset 格式，第三方格式需先转换。
- 「外部识别模块接口」接的是**模型**，不是**标签**。
- 结论：你现有的 XMP/Excel 历史标签资产，**无法直接导入 ICDMS**，需二次开发转换或向厂商确认是否有导入工具。

### 6.4 费用

- **手册明确收费**：LLM 类 AI 功能（4.9 节全部功能）需申请 API KEY（`lcdms_llm_` 开头），**消耗账户余额**，余额与本机累计用量可在账户窗口查看。
- **版本分层（官网/公众号证实）**：存在「社区版」与「教育版」（教育版需扫码填表申请）；具体免费范围、额度上限、社区版/教育版差异，**手册与公开渠道均未披露**。
- **未公开价格**：自动识别、自主模型训练等本地能力是否收费、有无免费额度、商业授权价格——均无公开价目表，需联系 ICDMS 团队（<icdms-contact@linkdatasets.com>）确认。
- 「软硬件一体方案」属商业化合作，需单独洽谈。
